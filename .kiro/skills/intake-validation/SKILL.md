# Intake Validation

## Owner
Agent 02 — Intake Analyst.

## Shared Use
Agent 01 may read this skill for routing awareness. No other agent owns intake validation.

## Purpose
Turn the user's initial request into a complete, bounded intake without inventing missing requirements.

## Steps
1. Read the user's request and existing INTAKE.md / PROJECT_REQUIREMENTS.md.
2. Identify only missing information that materially blocks downstream work.
3. Ask the minimum necessary clarification.
4. Record confirmed goals, constraints, target users, environment, required integrations, visual requirements, and explicit exclusions.
5. Mark unresolved non-blocking assumptions clearly.
6. Validate that the intake is sufficient for the next workflow gate.
7. Hand back to Agent 01.

## Hard Stop
Do not define product architecture, technical architecture, implementation, or final feature scope.
